# Evaluation

## The benchmark: TemporalEvidenceBench

Eight categories, each constructed to isolate one failure mode.

| category | setup | correct behaviour | what fails it |
|---|---|---|---|
| `CURRENT` | 3 successive CEOs (2024, 2025, 2026) + a 2026 blog *about* the 2024 one | name the 2026 CEO | quoting an earlier valid state as current |
| `HISTORICAL` | same documents, asked "in 2024" | name the 2024 CEO | answering with the current state |
| `CHANGE` | same documents | **all three** states with effective dates | reporting only the latest |
| `CONFLICT` | two credible sources, same period, 15 vs 12 offices | report both, unresolved | silently picking either |
| `MULTI_HOP` | acquisition doc + acquirer's CEO doc | chain both hops | answering from one hop |
| `INSUFFICIENT` | documents about the entity, nothing about the attribute | abstain | any confident answer |
| `OUTDATED_SOURCE` | only 2023 evidence for a "current status" question | answer **with a staleness qualifier** | stating the stale value as current |
| `CROSS_SOURCE` | 1 wire story + 2 syndicated reprints + 1 filing | 2 independent sources, not 4 | counting reprints as corroboration |

The last two are the ones worth arguing about. `OUTDATED_SOURCE` fails a system
that produces the right *string* without the qualifier — string matching alone
would score it correct. `CROSS_SOURCE` fails a system that inflates
corroboration through syndication, which is behaviour that scores *well* on
every other benchmark and is exactly how a system talks itself into a false
fact.

### Why not an existing benchmark

NQ, HotpotQA, TriviaQA and FEVER assume a static corpus with one right answer.
They have no label for *"correct in 2024, wrong now"*, none for *"the sources
disagree, say so"*, none for *"abstain"*. A system quoting a stale source scores
identically to one quoting the current source. Those missing labels are the
entire subject of this project, which is why the benchmark had to be built.

TimeQA and StreamingQA come closest on the temporal axis, but carry no
conflict, abstention, staleness-qualifier or source-independence labels.

### Construction

The seed set is **hand-written**, not LLM-generated: a benchmark generated by a
model inherits that model's errors and cannot be used to measure a system that
uses the same model. `expand_synthetic()` scales it by substituting only names,
dates and values — the *labels* stay exactly as hand-written. That buys
statistical power without importing a generator's errors into the gold answers.

## The ablation ladder

| system | adds |
|---|---|
| B1 LLM-only | nothing — measures what the weights memorised |
| B2 Basic RAG | dense top-k |
| B3 Hybrid RAG | + BM25 + fusion + reranking |
| B4 Temporal RAG | + freshness and validity signals |
| VERITAS | + bitemporal store, agentic loop, claim verification, contradiction analysis, abstention |

All five share **one corpus, one tokenizer, one set of weights**. Only the
pipeline differs. Comparing against a differently-trained model would confound
*"my architecture is better"* with *"my model is bigger"* — the most common way
benchmark tables mislead.

**B4 → VERITAS is the row that carries the claim.** B4 is the strongest
*published* pattern and the honest bar. If VERITAS does not beat it on
`CONFLICT`, `INSUFFICIENT` and `OUTDATED_SOURCE`, the extra machinery is not
earning its complexity and the honest thing is to report that.

## Metrics, and why each one

### Retrieval

Retrieval is the ceiling on everything downstream — evidence not retrieved
cannot be verified.

* **Recall@k** — fraction of gold documents in the top k.
* **Precision@k** — every irrelevant chunk is context the verifier must reject.
* **MRR** — `1/rank` of the first gold hit; rewards getting one right answer to
  the top, which is what a single-fact question needs.
* **nDCG@k** — `DCG/IDCG` with a `log₂(1+rank)` discount. The headline number,
  because it is the only one of the four handling graded relevance *and*
  position together.

Note: retrieval returns **chunk** ids (`doc#3`) while gold labels are
**document** ids. The harness maps chunk→document before scoring; comparing them
directly scores every correct retrieval as a miss. (This was a real bug — the
first run reported recall 0.125 for every system.)

### Generation and grounding

* **evidence coverage** = supported claims / checkable claims. The metric the
  project is organised around. Opinions and non-checkable statements are
  excluded from the denominator, or a fluent answer gets punished for its
  connective tissue.
* **citation accuracy** — of the claims carrying citations, how many are
  actually `SUPPORTED`. Catches citation-shaped hallucination: a right-looking
  marker on an unrelated sentence.
* **unsupported claim rate** — the complement, reported separately because
  "high coverage" and "low unsupported" can diverge when many claims are
  `CONFLICTED`.

`coverage` and `cite_acc` are structurally `0` for B1–B4. They do not verify
claims, so there is nothing to measure. **That is the point of the column, not a
scoring trick** — and it should be stated that way rather than presented as a
win.

### Temporal

* **temporal accuracy** — 1.0 only if the answer states the right value **and**
  does not present a superseded value as current; 0.5 for the right value with
  stale framing. A plain string match cannot distinguish these.

### Conflict

* **contradiction detection** — counts true positives **and true negatives**.
  A system that never surfaces a conflict scores 7/8 on a set with one conflict
  item, so this column must always be read together with the `CONFLICT` row of
  the category table. Over-detection is the real failure: a detector that fires
  on every entity that ever changed trains the reader to ignore the conflicts
  section, which is worse than having none.

### Abstention

Reported as a **pair**, never a single number:

* **abstention precision** = correct abstentions / (correct + over-abstentions)
* **abstention recall** = correct abstentions / (correct + missed)

Trading one against the other is the entire design question. A system that
always refuses gets recall 1.0 and is useless; precision is what catches it.
`AbstentionScore` exposes both plus the F1.

### Freshness

* **freshness lag** — wall-clock time between a new source appearing and the
  answer changing, via `freshness_lag()`. A system requiring a re-index or a
  retrain cannot produce a number here at all. That is the point of the metric.

## Reading a result honestly

**Defensible from this harness:**

* VERITAS is the only configuration that abstains when evidence is absent,
  surfaces conflicts instead of silently picking, and qualifies stale evidence.
* Claim-level coverage and citation accuracy are measurable for VERITAS and
  structurally undefined for the baselines.
* New information reaches answers in milliseconds without retraining.
* The categories where the ladder is flat until VERITAS (`CONFLICT`,
  `INSUFFICIENT`, `OUTDATED_SOURCE`) name the capabilities the architecture adds.

**Not defensible:**

* Any number from a run **without a trained checkpoint**. With a random encoder
  dense retrieval is noise and the table swings between runs. Always pass
  `--checkpoint checkpoints/sft.pt`.
* Any absolute accuracy from the 8-item seed set treated as a population
  estimate. Expand first.
* Comparison against a frontier LLM at open-domain QA — this model is ~30M
  parameters, and the architecture is explicitly designed so that the model is
  not the thing being trusted.
* Calibration claims. The evidence score is a weighted heuristic reported as a
  **label**, not a probability. Calibration would require reliability diagrams
  against held-out ground truth, which this harness does not produce.

## Reproducing

```bash
python tests/test_smoke.py                                         # correctness gate
python scripts/run_eval.py --synthetic 5 --checkpoint checkpoints/sft.pt
python scripts/run_notebook.py notebooks/08_evaluation.ipynb       # same, with plots
```

`run_eval.py` seeds torch before building the model so runs are reproducible.
Note that the random-init path is *reproducibly random*, not meaningful — seeding
removes variance, it does not create signal.

## Extending the benchmark

Highest value additions, roughly in order:

1. **More hand-written items in your own domain.** The seed set defines the
   categories; volume has to come from somewhere trustworthy.
2. **A `CORRECTION` category** — a source that retracts a claim. This exercises
   the transaction-time axis, which no current item tests.
3. **A `MULTI_ENTITY` category** — the same attribute across entities that get
   confused by the entity linker.
4. **Negative controls for conflict** — near-identical values that must *not* be
   reported as a conflict (rounding, scope). Over-detection needs test coverage
   as much as under-detection does.
5. **Real dated documents.** Synthetic dates are clean; real filings have
   effective dates buried in prose, which is where temporal extraction actually
   breaks.
